# Deploying SURAKSHA for free (Supabase + Render)

The database is on **Supabase** (free Postgres + PostGIS). The API and the dashboard run as one free
**Render** web service, built from this GitHub repo. No credit card is needed for either.

```
Browser ──HTTPS──> Render web service (FastAPI + built dashboard, one Docker container, 512 MB)
                          │  DATABASE_URL (SSL)
                          ▼
                   Supabase Postgres + PostGIS
```

The data pipeline stays on your laptop; `deploy/push_db.py` uploads its results.

---

## Step 1: Supabase database (done)

Project created; `deploy/space.env` holds its **Session pooler** URI.

Notes for a new project:
- Use **Connect → Session pooler**, not "Direct connection" (cloud hosts need the IPv4 pooler).
- Special characters in the database password must be encoded in the URL: `@` → `%40`, `#` → `%23`,
  `/` → `%2F`, `?` → `%3F`, `%` → `%25`, `:` → `%3A`. Or reset the password to letters and digits only.
- Save the file as `deploy\space.env` (copy of `deploy\space.env.example`); it is git-ignored.

## Step 2: Copy the database to Supabase (done)

```bash
docker compose up -d
```
```bash
.venv\Scripts\python deploy\push_db.py
```

Re-run it whenever you re-run the pipeline. It keeps the cloud's user accounts (add `--users` to overwrite them).

## Step 3: Push the code to GitHub

`.env`, `deploy/space.env` and `data/` are git-ignored, so no secrets or raw data are pushed.

```

```
```bash

```
```bash

```

The pull brings in teammates' commits first (otherwise GitHub rejects the push). If it reports a conflict in
`README.md`, keep their version of the conflicting part, then `git add README.md` and `git commit`.

If your branch is called `master`, push that instead. If the repo is **public**, the code is visible to anyone;
the data and secrets are not.

## Step 4: Create the Render service

1. Sign up at https://render.com with **GitHub** (no card needed for the free plan).
2. **New → Blueprint**, pick the repo `Hazard-Based-Red-Zone-Intelligent-Classifier`. Render reads `render.yaml`.
3. It asks for two values:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | The value of the `DATABASE_URL` line in `deploy/space.env` (everything after `=`) |
   | `GROQ_API_KEY` | A **new** Groq key from https://console.groq.com/keys (revoke the one shared in chat) |

   `JWT_SECRET` is generated by Render; `GROQ_MODEL` is preset.
4. **Apply**. The first build takes ~5–10 minutes (it builds the dashboard and installs Python packages).
   Follow it under the service's **Logs** until you see `Application startup complete`.

## Step 5: Open it

Your address is shown at the top of the service page, like `https://suraksha-xxxx.onrender.com`.
Sign in with the same accounts as locally (passwords in your local `.env`, `DEMO_PASSWORD_*`).

## Step 6: Check it, then change the passwords (before sharing the link)

Check first (uses the demo passwords from your local `.env`):

```powershell
$env:API_BASE = "https://suraksha-xxxx.onrender.com"; .venv\Scripts\python backend\check_auth.py
```

Then set new passwords directly in the cloud database (PowerShell, from the project folder):

```powershell
$env:DATABASE_URL = (Get-Content deploy\space.env | Select-String '^DATABASE_URL\s*=').ToString().Split('=', 2)[1].Trim().Trim('"')
.venv\Scripts\python -m backend.app.auth add ndrf.admin admin "NDRF Control Room"
.venv\Scripts\python -m backend.app.auth add sdma.uk sdma uk "Uttarakhand SDMA Officer"
.venv\Scripts\python -m backend.app.auth add sdma.od sdma od "Odisha SDMA Officer"
.venv\Scripts\python -m backend.app.auth add field.uk field uk "Field Reporter – Chamoli"
.venv\Scripts\python -m backend.app.auth add viewer viewer "Observer (read-only)"
Remove-Item Env:DATABASE_URL
```

Each command asks for the new password.

## Updating the deployment

| What changed | Do |
|---|---|
| Code | `git push` — Render rebuilds and redeploys automatically |
| Data (pipeline re-run) | `.venv\Scripts\python deploy\push_db.py`, then **Manual Deploy → Restart** on Render |
| A secret | Render service → **Environment** → edit → Save (restarts the service) |

## Free-tier behaviour to know

- **The service sleeps after 15 minutes without visitors.** The next visit takes about 1–2 minutes while it
  starts and loads the data. Open the link a few minutes before a demo. The hourly rain refresh runs only while
  it is awake (and once at every start).
- **750 free hours per month** cover one service running all month.
- **Supabase pauses a free project after ~7 days of inactivity.** Un-pause it from the Supabase dashboard.
- **Field-report photos** are stored on the container's disk, which is wiped on every deploy or restart. The
  reports themselves (location, type, note) are in the database and survive.
- Memory: the app uses ~250 MB idle and ~380 MB at peak (PDF + allocation), inside the 512 MB limit.
- For government production, move to MeghRaj (NIC) or a MeitY-empanelled cloud in India.

## Troubleshooting

| Symptom in Render logs | Fix |
|---|---|
| `could not translate host name` / connection timeout | Use the **Session pooler** URI, not Direct connection. |
| `password authentication failed` | Wrong password, or an un-encoded `@`/`#` in it. Fix `DATABASE_URL` in Environment. |
| `Out of memory` / restarts | Should not happen (tested under a 512 MB limit); check nothing else was added to the image. |
| Login says `JWT_SECRET not configured` | Add a `JWT_SECRET` value in Environment. |
| Briefing says "template (AI unavailable…)" | `GROQ_API_KEY` missing or rate-limited; the template briefing still works. |
| `push_db.py`: connection refused on `localhost:5433` | Docker Desktop is not running: start it, then `docker compose up -d`. |
